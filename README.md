# Fabloom

Describe a data center network in plain language; get configs that are generated by NVIDIA
Nemotron on Nebius Token Factory, **verified with Batfish**, and repaired until every check
passes, or an honest report of what could not be fixed.

> Status: pre-alpha (week 1 of the build). Hackathon entry for the Nebius × NVIDIA Global
> AI Hackathon, and a long-term open-source project. Output is always a proposal for a human
> to review, never pushed to devices.

## Results

**No benchmark numbers yet.** The harness is built and tested offline; it has not run
against real models or a real Batfish. The v0.1 benchmark (40–60 scenarios) compares five
arms from `conf/bench.yaml`: raw Nano, Super and Ultra, Super with the repair loop, and the
routed product. The verify-only result is the repair arm's first-pass rate; repair + doc
grounding is added with the Tavily step. Its report is generated into
`docs/benchmark/v0.1.md`, with every number annotated with how it was measured and negative
results included.

What exists and is tested today (offline, `make check`):

| Piece | State |
|---|---|
| Deterministic fabric plan + check compiler | 20 pilot scenarios compile; allocator property-tested (no overlaps, order-independent, never renumbers) |
| Run state machine, budget, event log | Tested with scripted models and verifiers; golden path end to end |
| Token Factory client | Strict JSON output, retries, refusal/truncation detection, cost accounting, secret scrubbing |
| Batfish verifier | Question mapping tested against **synthetic** answers only; real recordings come from the week-0 spike |
| Benchmark harness | Arms x scenarios through the real loop, resumable; records derived from event logs; MLflow tracking; regression and grounding gates; generated report |
| Nebius Sandboxes backend | Not built. Spike script ready (`spikes/batfish_in_sandbox.py`) |

## The one rule

**The model cannot influence what it is graded on.** Checks are compiled deterministically
from the intent (`src/fabloom/checks/`); the verifier (`src/fabloom/verify/`) and the model
side (`llm/`, `agent/`) cannot import each other. import-linter enforces this in CI
([ADR-0001](docs/decisions/ADR-0001-verification-independence.md)).

## How it works

```
request ──► planner (Nemotron Nano) ──► intent JSON
            deterministic allocator  ──► fabric plan (addresses, ASNs, sessions)
            deterministic compiler   ──► checks
            generator (Nemotron Super) ──► per-device configs
            pre-lint gate ──► Batfish ──► report ──┐
            repairer (Super, escalating to Ultra) ◄┘ until pass or budget/rounds exhausted
            explainer (Nano) ──► plain-language summary
```

Every step is an event in `runs/<run_id>/events.jsonl`; the CLI's `--watch` just tails it.

Each report states its verification level: **L2**, statically verified with Batfish, is
what this release targets. L0 means nothing could be checked.

## Quick start

```bash
make install                     # uv sync --frozen --extra batfish --extra eval + pre-commit
cp .env.example .env             # add FABLOOM_TOKEN_FACTORY_API_KEY
make batfish-up                  # local Batfish on :9996

uv run fabloom plan benchmark/v0.1/leaf-spine-ebgp-0004.yaml    # no model, no network
uv run fabloom generate "2 spines, 4 leaves, eBGP underlay, one private ASN per leaf" --platform frr
uv run fabloom doctor            # every configured Nemotron model exists and answers JSON

uv run fabloom bench run --dry-run                 # the arm x scenario matrix and its worst-case spend
uv run fabloom bench run --arm super-repair        # runs, reports, gates, logs to MLflow
uv run fabloom bench report runs/bench/<id> --report docs/benchmark/v0.1.md   # no model
```

Models, prices and routing: `conf/models.yaml`. Run budget: `conf/fabloom.yaml`. Benchmark
arms and gates: `conf/bench.yaml`.

## Known limitations

- **Prices and model IDs are unconfirmed.** Every entry in `conf/models.yaml` is
  `price_verified: false` until `spikes/nemotron_probe.py` runs; unknown prices are set
  pessimistically so the budget guard over-estimates spend.
- **FRR traffic filters cannot be verified.** `frr.conf` has no packet filter and Batfish
  does not model iptables, so "block SSH" on FRR is reported as *not verifiable* rather than
  passed. Filter scenarios use Arista EOS ([ADR-0006](docs/decisions/ADR-0006-deterministic-fabric-plan.md)).
- **The Batfish evaluator has only seen synthetic answers.** Column names follow Batfish's
  documented answer schemas; `scripts/record_batfish_fixtures.py` replaces them with real
  recordings, which `tests/integration/test_recorded_fixtures.py` then replays.
- **FRR packaging for Batfish** (Cumulus concatenated format) is unconfirmed against a live
  server.
- Leaf-spine eBGP underlays only: FRR and Arista EOS, numbered and unnumbered.
